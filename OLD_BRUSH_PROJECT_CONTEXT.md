## 4 · Architecture

- Next.js 16 · App Router · React 19 · TypeScript `strict`.
- Server Components by default. Client islands only when justified:
  - `Preloader` — GSAP timeline + sessionStorage guard.
  - `Header` — scroll state + mobile drawer.
  - `ScrollReveal` — GSAP scoped useGSAP.
  - Contact form (Fase 3).
- Tailwind CSS v4 with tokens declared in `@theme` inside `globals.css` — no `tailwind.config.js`.
- Aliases: `@/components/*`, `@/lib/*`, `@/app/*`.
- Content and SEO helpers centralised in `src/lib/content.ts` and `src/lib/seo.ts`. Never inline commercial copy inside a component.

## 5 · Component boundaries

| Layer | Rule |
|---|---|
| Atoms | Presentational only. Accept explicit surface variants (`paper`, `sand`, `green`, `lightgreen`, `gold`). |
| Molecules | Compose atoms + light behaviour. Never fetch data. |
| Organisms | Own a whole section (Header, Footer, HeroBrush, etc.). Consume content from `lib/content.ts`. |
| Templates | Reserved. Only introduce if two organisms share layout scaffolding. |

**Visual differentiation is enforced by design:**

- `Button` = interactive. Never fake as chip.
- `MetaChip` = passive informational label. No hover, no cursor pointer, no border.
- `Divider` = editorial ornament (never as content separator between paragraphs).
- Text link ≠ Button. Never restyle a link to look like a button.

## 6 · Animation categories

Five categories, **kept separate**:

1. **`brushRevealOnce`** — one-shot entry, `ScrollTrigger.once: true`. Currently in `ScrollReveal` molecule.
2. **`plasterScrub`** — scrub-linked to scroll. Reserved for ornaments (Fase 2).
3. **`hoverBrushGlow`** — micro-interactions. Already present as `ServiceCard`'s image zoom (`scale-[1.04]`, `--duration-slow` / `--ease-brush`); `GalleryBento` tile images now reuse the same token-driven hover-zoom inside their `overflow-hidden` tile — the tile itself never resizes, so nothing reflows.
4. **`preloaderTimeline`** — one shot on first visit per session. Owned by `Preloader` molecule.
5. **`quoteStepSwap`** — one shot per step change inside the quote modal, driven by the step index (never scroll-linked). Owned by `QuoteFlow` organism. Outgoing/incoming direction follows the travel direction: forward slides up from `y: +32`, back slides down from `y: -32`, `0.42 s`, `power3.out`. Tweens **`opacity`, never `autoAlpha`** — `autoAlpha` sets `visibility: hidden` on the from-state, and `useGSAP` is a layout effect, so the step's autofocus effect would fire against an unfocusable subtree and leave the caret on `<body>` (Enter then does nothing).

Never mix categories in a single helper. All animations respect `prefers-reduced-motion`.

- **2026-09-12 · iOS rotation bug fixed — grid items, not paint.** Rotating an iPhone to landscape and back left the page rendered at ~57%, with the Services cards and Gallery images spilling past the viewport. Diagnosed by instrumenting a real device (headless Chrome could not reproduce it in any scenario — the emulated rotation always recovered cleanly).
  - **Root cause: `min-width: auto` on grid items.** Measurements from the device showed the grid *container* correctly back at 362 px while the *item* stayed at its landscape 686 px: `card:686 < data-reveal:686 < home-services-card-grid:362`. A grid item's default `min-width: auto` ties its width to its intrinsic size, and iOS WebKit kept the intrinsic size cached from landscape. Fix: **`min-w-0 w-full` on every direct grid child** in `ServicesGrid` and `GalleryBento`.
  - **The stuck page zoom was a symptom, not a cause.** With the items still 686 px wide the document overflowed a 402 px viewport, so iOS zoomed out to fit: `visualViewport.scale` measured 0.569, and 402/706 = 0.569. Fixing the item width removed the zoom.
  - **Two hypotheses the measurements killed**, both recorded so nobody re-tries them: there is no horizontal overflow at any breakpoint (`scrollWidth === clientWidth` at 375/390/768/1024/1440), and no desktop breakpoint was ever active on the phone (`lg` stayed false throughout, so `lg:max-w-[26vw]` on the hero copy was never the culprit).
  - `ScrollReveal` and the Hero copy tween gained `clearProps: 'transform,opacity'`. This did **not** fix the bug — the device showed the item stale with the transform already cleared — but a permanent identity transform needlessly promotes every revealed element to its own composited layer, so it stays.
  - `backdrop-blur` removed from the fixed `<header>` and the floating menu toggle, and the mobile drawer is now `invisible` when closed instead of merely `opacity-0`. Also not the cause, also kept: the drawer's links were focusable while the menu was shut, which was a real accessibility bug.
